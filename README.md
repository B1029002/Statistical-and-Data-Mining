# CE5033 Final Project — Motorcycle Specifications Analysis 

A hybrid **statistics + data-mining** study of the Bikez.com motorcycle catalogue
(**42,564 motorcycles × 105 fields**) for *CE5033 Statistical Methods and Data Mining*.

> **Read [`REPORT.md`](REPORT.md) for the full analytical write-up, results and presentation outline.**
> This README is the codebase / reproducibility guide.

---

## 1. Question

**What technical specifications define a motorcycle's "type", and how do engine, weight and
performance variables relate to one another?** We attack it with a hybrid methodology:
classical statistics (hypothesis testing, regression) **and** data mining (classification,
clustering, association rules).

## 2. Headline results

| Technique | Result |
|---|---|
| Two-sample test | Liquid- vs air-cooled power: **74.9 vs 30.2 HP**, *t* = 37.6, *p* < 10⁻²⁶³, *d* = 1.03 |
| ANOVA + Tukey | category explains **η² = 37 %** of power variance; 48/55 pairs differ |
| OLS regression | log–log top-speed model **R² = 0.89**, power exponent **0.43** (≈ aero cube-root) |
| Classification | Random Forest predicts 8 categories at **79.8 % accuracy** (macro-F1 0.76) |
| Clustering | K-means finds **3 segments**: commuter / cruiser / sport |
| Association rules | *{big engine + belt drive} ⇒ cruiser* (conf 0.86, lift 6.1) |
| Paired tests (t / Wilcoxon / sign) | bore vs stroke: engines are **oversquare** (+8.0 mm), all *p* ≈ 0 |
| Two-proportion z-test | injection share **64 %** (≥2010) vs **23 %** (<2010), *z* = 34.3 |
| Predictive regression | RF top-speed model: **RMSE 17.6 km/h, MAE 9.4, R² 0.91** |

## 4. How to run

```bash
# 1) create the environment (one time)
conda create -n data_mining python=3.11 -y
conda activate data_mining
pip install -r requirements.txt

# 2) run the full pipeline (~1–2 minutes)
bash run_all.sh

# …or run a single stage
cd src && python 03_statistics.py
```

`run_all.sh` auto-selects the `data_mining` conda interpreter and runs stages 1→4 in order.
Stages 2–4 depend only on the cleaned files from stage 1, so the result is fully reproducible
from the raw CSV. Everything is deterministic (`random_state = 42`).

## 8. Notes on reproducibility & rigour

- **No data leakage**: imputation/scaling are fit inside cross-validation pipelines.
- **Robust statistics**: every test is paired with a non-parametric counterpart and an effect size.
- **Verified parsing**: regex extraction was spot-checked against raw strings; physical bounds
  catch real data-entry errors.
- See `REPORT.md` §9 for the full code review / self-evaluation.
